# 任務：產業分類更正後，改寫產業分析草稿

137 家公司已依年報更正產業分類，更正表在 `research-site/data/industry-corrections.csv`。每個產業的分析草稿在 `research-site/data/industry-analysis/{slug}.md`，這些草稿現在要跟著改。

## 草稿規則（由檢查程式強制執行）

- 每一句結尾都要有至少一個事實標記，例如 `〔2330-AR-08〕`。
- 引用的事實必須存在、通過查核，而且屬於**本產業**的公司。「本產業」以更正後的分類為準。
- 句中的每個數字都要出現在引用事實的原文裡。股票代號例外，例如「公司（2330）」中的代號。
- 要沿用既有的寫法：小節標題（業務型態與產品／營收結構與市場分布／供應鏈：原料、供應商與客戶／研發與人力／發展計畫）、第一次提到公司時寫「公司（代號）」、年度寫成「114年度（2025）」、公司自述要寫「於年報自述」。
- 不可寫自然人姓名；匿名代號照原樣寫；不可加入年報沒有的評價。

## 你的工作：`draft_jobs_K.json` 裡的每個 slug

1. **移出（moved_out）**：刪掉或改寫草稿中引用這些公司事實的句子。
   - 如果一句同時提到其他公司，只拿掉被移出公司的部分，並保持句子通順。
   - 刪完後如果某個小節變空，就刪掉整個小節標題。
2. **移入（moved_in）**：為每家移入公司，在**對應的小節**補寫 1～3 句介紹它的主要業務和營收結構，有供應鏈或研發資訊也可以補。
   - 素材有兩個來源：
     - 該公司的已查核事實：`research-site/ops/shorts/base/{ticker}.json` 的 `facts`。
     - 原產業草稿裡關於它的舊句子：`git show HEAD:research-site/data/industry-analysis/{from_slug}.md`。這些舊句子已經查核過，可以改寫後沿用。
   - 文字要能自然融入本產業的敘述，不要另外開一個「新增公司」小節。
3. **新草稿（new_draft = true）**：從零寫一份完整草稿，格式照其他草稿（例如 `railroads.md`）。開頭必須是 `## 產業分析 {.unnumbered}`。

## 驗證（必做）

每改完一個 slug，就在 `research-site` 資料夾執行：

```
py scripts/generic/build_industry_analysis.py --check-only <slug>
```

執行時要設定環境變數 `PYTHONIOENCODING=utf-8`。一直修到該 slug 顯示 OK 為止。

全部改完後，再對你負責的所有 slug 一起跑一次。

## 限制

- 只修改你負責的那些 `data/industry-analysis/{slug}.md`，其他檔案一律不動。
- 不可上網。
- 最後回報：每個 slug 刪掉幾句、新增幾句、最終檢查的結果。
